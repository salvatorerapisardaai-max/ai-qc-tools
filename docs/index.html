Un punteggio di qualità su cui bloccare una build.

La review “a sensazione” non scala. Le suite di analisi statica complete sono pesanti per i progetti piccoli. ai-qc-tools sta nel mezzo: uno script, zero configurazione, un numero da 0 a 100 e un exit code.

01

La scelta di progetto che conta: l’AI è opzionale

Senza chiave API lo strumento è completamente offline e deterministico. Con una chiave, la review del modello si somma ai risultati statici invece di sostituirli.

static Deterministico, senza secret

Lo stesso input produce sempre lo stesso punteggio: si può eseguire in CI su un fork, senza credenziali. Controlli su AST per la struttura reale del codice, più controlli riga per riga per ciò che l’AST non vede.

+ claude Review da senior, a budget noto

Solo gli N file più rischiosi (default 5) vengono inviati a Claude, con il sorgente troncato a 6 000 caratteri per restare in un budget di token prevedibile. Il pacchetto anthropic è importato in modo lazy: chiave assente o chiamata fallita ricadono sulla sola analisi statica invece di far crashare il tool.

Nella CI, senza secret

Il workflow installa le dipendenze, esegue i test, lancia l’analizzatore con --no-ai e carica il report come artifact della build. Sotto 60, la build fallisce.

qc.yml — github actions
$ python ai_qc.py ai_qc.py --no-ai # 🤖 AI Quality-Control Report Quality score: 70/100 Files analysed: 1 Findings: 0 high · 0 medium · 25 low AI review: static-only (no API key) exit 0 $ python ai_qc.py bad.py --no-ai Quality score: 10/100 Findings: 2 high · 0 medium · 3 low exit 1 — build failed
04

Stack e test

  • Python 3.10+ solo standard library per l’analisi
  • ast · argparse · dataclasses · pathlib · json
  • anthropic ≥ 0.40 opzionale
  • pytest ≥ 8 6 test end-to-end
  • GitHub Actions gate sulla build

Prompt versionati

prompts/code_review.md documenta il prompt e il ragionamento dietro ogni sua parte. È un artefatto revisionabile come qualunque altro sorgente, non una stringa sepolta nel codice.

Sei test, i punti che contano

Un file pulito non produce risultati di gravità alta; bare-except ed eval vengono segnalati; gli errori di sintassi sono intercettati invece che sollevati; il punteggio distingue il codice buono da quello cattivo; il conteggio righe gestisce file vuoti e newline finali.

“Volevo un modo riproducibile per tenere la qualità misurabile invece che affidata alle sensazioni. Trattare il prompt come un artefatto versionato e revisionabile fa parte della stessa idea.”
